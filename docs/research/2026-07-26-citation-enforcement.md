# Принуждение к цитированию: обо что оно спотыкается

Ресёрч 2026-07-26. Проверка решения «каждое утверждение обязано ссылаться на id
фрагмента, иначе бриф не сохраняется».

**Решение по итогам: проверки существования id недостаточно. Требуем дословную
цитату + id, проверяем вхождение строки детерминированно.**

## Как ломается наивная проверка «ссылка есть»

- **Post-hoc rationalization** — модель пишет утверждение, потом подбирает фрагмент с
  поверхностным лексическим совпадением. В разборе 2025 года — 57% цитат в RAG такие.
  (Цифра из блога, не peer-reviewed; порядок согласуется с данными ниже.)
- **Разрыв валидности и верности.** «Cited but Not Verified» (PwC, 2026, 14 моделей,
  deep research): link validity >94%, topical relevance >80%, а фактическая
  подтверждённость цитаты — **39–77%**. Все дешёвые формальные слои проходят почти
  всегда, осмысленность проваливается у каждой второй-третьей цитаты.
- **Больше поиска — хуже цитаты.** Там же: fact-check accuracy падает в среднем на
  ~42% при росте tool calls с 2 до 150. Прямо против режима `deep`.
- **Fabrication ссылок при свободной генерации:** по 13 LLM доля галлюцинированных
  ссылок 14–95% (55% у GPT-3.5, 18% у GPT-4).
- **Reward hacking верификатора** — если проверку делает обучаемый checker в петле
  (arXiv 2605.25988, checker-guided RAG).
- **Ложные срабатывания NLI:** ALCE — citation recall ~85%, precision ~77.6%, высокий
  FP на частичной поддержке. Автопроверка сама не идеальна.

## Anthropic Citations API — что реально гарантирует

Цитата возвращается как start/end char index, вычисленные системой, а не сгенерированные
моделью. Гарантия: **позиция существует в документе**, текст не выдуман. Anthropic явно
оговаривает: «cited position exists» ≠ «interpretation is correct» — то есть привязку
не того куска API не закрывает. Ограничения: только текст; цитаты включаются для всех
документов запроса или ни для одного. У OpenAI/Google grounding-метаданные дают гарантию
того же уровня.

## Про Grounding Enforcer из плана

`steveswain14/mcp-hallucination-suite` существует (Glama, Lobehub): кросс-проверка
вывода против retrieved sources, флаги claim/statistic/attribution/quote/URL.
**Независимых оценок, бенчмарков, звёзд или отзывов не нашлось** — непроверенный проект
одного автора. Вычеркнут из обязательного чтения.

## Что реально помогает и почём

- **Дословная цитата вместо/вместе с id** — exact string match в исходном фрагменте.
  Детерминированно, бесплатно, ловит фабрикацию и подмену фрагмента. Это же по сути
  делает Citations API. **Взято в дизайн.**
- **Anchored citation при генерации** вместо post-hoc сопоставления — заявлено −61%
  галлюцинированных цитат.
- **Post-hoc NLI** (entailment фрагмент → утверждение), ALCE/VeriCite. Дешёвая модель
  DeBERTa-класса, единицы мс на пару. Ловит «цитата дословная, но утверждение не
  следует». → это и есть этап 3.
- **Quote-first генерация** (сначала извлечь цитаты, синтез только из них) —
  Pleias-RAG. Структурно самое надёжное, дороже по токенам.

## Вердикт

Жёсткая проверка «id существует» закрывает только фабрикацию идентификаторов — то, что
и так проходит на 94–100%. Тот failure mode, которого мы боялись (ссылка на ближайший
фрагмент), проходит её в 100% случаев. Хуже: создаёт ложное чувство защищённости и
поощряет ставить любой id.
