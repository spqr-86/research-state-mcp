# Stage 2 — briefs, citations and the research process

Date: 2026-07-26. Status: approved by Petr, ready for an implementation plan.

Stage 1 gave the server memory (jobs, subquestion plans) and fragments. Stage 2 makes
the output of a research run durable and checkable: a brief the server will not accept
unless every claim carries a quote that provably came from a page we fetched.

## Decisions taken during brainstorming

1. **Hard invariant, not a warning.** A brief with an unsupported claim is rejected, not
   saved-with-a-note. A warning that blocks nothing gets ignored by the third time.
2. **The brief arrives as a structure, not prose.** The server has no model and cannot
   read text; a list of claims is the only form it can check exactly. The markdown file
   is generated by the server from that structure, so readability is not lost.
3. **Scope:** core (`research_finish`, fragment ids, `brief_search`, brief files, the
   skill, the `research.md` rewrite) plus `research_gaps` and the saved-context counter.
   Brief staleness is deferred.
4. **Orchestration: planning in the main context, fetching in a subagent** (option В).
   The subagent returns urls and fragment ids — never page text.

Three of these were revised by research before implementation — see below. That is the
point of checking before building, not after.

The full research behind every claim in this document lives in `docs/research/`, one
file per question, with sources: orchestration split, structured output vs reasoning,
citation enforcement, fragment provenance. Read those before re-litigating a decision.

## What research changed

### Existence of a citation is worth almost nothing

Measured across 14 models in deep-research mode (PwC, *Cited but Not Verified*, 2026):
link validity above 94%, topical relevance above 80%, but actual factual support of the
cited claim only **39–77%**. The failure mode this design feared — attaching the nearest
plausible fragment id so the check passes — passes an existence check 100% of the time.
Anthropic's own Citations API states the same limit explicitly: it guarantees the cited
position exists, not that the interpretation is right.

Worse, the same study finds fact-check accuracy falling ~42% as tool calls grow from 2
to 150 — citation quality degrades exactly as research gets deeper, which is the mode
this project exists to support.

**Change:** a claim must carry `fragment_id` **and the verbatim quote**. The server
checks the quote is literally contained in the stored fragment text. Deterministic, no
model, no cost. It cannot be satisfied by pointing at an arbitrary fragment.

`mcp-hallucination-suite` ("Grounding Enforcer"), listed in the original plan as
required reading, turns out to be an unreviewed single-author project with no
benchmarks. Dropped from required reading.

### Structured output can cost reasoning quality

The 2024 paper behind the "structure harms reasoning" claim was methodologically
criticised (different prompts in the structured and free branches), but the effect is
real and scales inversely with model headroom: noise-level on Sonnet-class models,
−30 points on small ones, −5 points on Opus for competition maths under a hard schema.
The mechanism is mundane — the model starts solving the task while emitting the first
field. Decoupling reasoning from formatting recovers 80–87% of the loss.

**Change:** the brief is produced in two steps — a free-form analytical pass over the
fragments, then a separate call that packs the result into the schema. The schema stays
flat; `fragment_id` and `quote` are required per claim, nothing else is.

### Fragment identity is a solved problem

W3C **Web Annotation Selectors** already model this: `TextQuoteSelector` (exact text
plus prefix/suffix context) combined with `TextPositionSelector` (offsets). Hypothes.is
data shows why the quote half matters: 27% of annotations are already orphaned by page
changes, 61% more are at risk, and web archives recover only 12% of the lost ones. A
bare hash tells you "no match" and nothing else.

**Change:** a fragment record stores the exact text snapshot, 32 characters of prefix
and suffix, offsets, and the page's fetch time. Re-verification has three outcomes —
`exact`, `re-anchored` (found by quote at a new offset), `orphaned` (gone; the snapshot
is shown instead).

`arXiv 2606.18037` ProvenanceGuard is real and sits *above* this schema rather than
competing with it — useful input for stage 3.

## Architecture

New module boundaries, following stage 1's rule that logic lives outside the MCP layer:

```
src/research_state/
  briefs.py     # brief validation, storage, FTS5 search   (new)
  fragments.py  # + persistence of issued fragments        (extended)
  metrics.py    # context-saved counter                    (new)
  server.py     # thin adapters                            (extended)
```

### Fragment persistence

`fragments_for` stops being stateless. Every fragment it hands out is written to
`issued_fragments`:

| column | meaning |
|---|---|
| `fragment_id` | `sha256(url + start_offset + fetched_at)`, first 16 hex chars |
| `url`, `job_id` | provenance and which research asked |
| `exact` | snapshot of the fragment text |
| `prefix`, `suffix` | 32 characters of context each, for re-anchoring |
| `start_offset`, `end_offset` | position in the page text at fetch time |
| `fetched_at` | the cache's own timestamp for that page |

The id is checked against this table, so no signature or HMAC is needed — the threat is
a model inventing an id, not an attacker forging one.

### `research_finish(job_id, summary, claims[], gaps[])`

- `summary` — free prose, the synthesis; not claim-checked.
- `claims[]` — `{text, fragment_id, quote, kind}` where `kind` is `fact` or `assumption`.
  A `fact` must have both `fragment_id` and a `quote` contained in that fragment's
  `exact` text. An `assumption` needs neither, but is rendered as an explicit assumption
  in the brief, so unsupported reasoning is possible but never invisible.
- `gaps[]` — what was not found. Required to be non-empty *or* every subquestion closed;
  see `research_gaps`.

Rejection returns the offending claims with the reason (`unknown_fragment`,
`quote_not_found`, `missing_citation`) and saves nothing.

On success the server writes `~/knowledge/research/YYYY-MM-DD-<slug>.md` — the file is
the source of truth, the FTS5 index is derived and rebuildable — and returns the path
plus a five-line summary, not the brief text.

### `research_gaps(job_id)` and honest closing

Returns open subquestions. `research_finish` refuses a job with open subquestions unless
each is accounted for in `gaps[]`. This is what stops the ReAct failure mode where the
model stops when it decides it is done.

### `brief_search(query)`

FTS5 over brief summaries and claim texts, `unicode61`. Returns title, path, date, age
in days, and matching snippets — never the brief body. `research_start` runs the same
search on the topic and returns the top 3.

### `verify_claim(claim, url)`

Unchanged from the plan: returns fragments plus `verdict="unverified"`,
`method="quote-match"`, `confidence=null`. The contract exists so stage 3's NLI model
changes nothing outside this function.

### Metrics

One row per `fragments_for` call: `paragraphs_total`, `paragraphs_returned`,
`chars_total`, `chars_returned`. `research_state_stats()` sums them. This is the only
non-rhetorical evidence that the project is worth anything, so it starts collecting from
day one rather than being added once there is a reason to want the number.

## Process (the skill)

1. `research_start` → check returned briefs first. A repeat question ends here.
2. Plan 3–5 subquestions (`research_plan`), narrowing the search area by domain,
   category and freshness per the table in the plan; always name the year.
3. Delegate search and fetching to the `research` subagent; it returns urls only.
4. `fragments_for` per url and subquestion — never `fetch` in the main context.
5. `research_mark` per closed subquestion; `research_gaps` before finishing.
6. Free-form synthesis, then a second call packing it into `research_finish`.

One simple question does not get a subagent — Anthropic spent months fixing exactly that
over-delegation, so the rule is explicit from the start.

## Errors

Every tool returns `{"error": <code>, ...}` rather than raising: unknown job, unknown
fragment, quote not found, cache miss. The client can act on all four without a stack
trace, and a failed brief never half-writes a file.

## Testing

- Unit: quote containment (including whitespace and unicode normalisation), rejection
  paths, fragment id stability, FTS5 search, gap enforcement.
- Property-ish: a claim whose quote is one character off must be rejected — the check is
  literal on purpose.
- Smoke, extended: plan → fragments → finish → `brief_search` finds the new brief →
  a second `research_start` on the same topic returns it.
- Non-determinism: nothing asserts on model output; the server is deterministic and is
  tested as such.

## Definition of Done (stage 2)

- [ ] `uv run pytest` and `-m smoke` green
- [ ] A brief with a fabricated or mismatched quote is provably rejected (test)
- [ ] A real research run produces a file in `~/knowledge/research/` where every fact
      carries a quote, checked by hand once
- [ ] Repeating that research returns the stored brief instead of searching
- [ ] `research_state_stats()` reports a non-zero saved-context figure
- [ ] `~/.claude/agents/research.md` rewritten — **requires Petr's console consent**
- [ ] PLAN.md §6–§8 updated
